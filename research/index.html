Method

How the labs work

We run three kinds of test, all on the computer the result is for. Unless a section says otherwise, it's an Apple M1 Max with 64 GB of memory.

Coding lab

Five tasks, 71 hidden tests

The model plans and writes the code alone, in a fresh folder. It never sees the tests it's graded on: invoice (17), recurrence (17), spreadsheet (17), fix-inventory (9) and todo-priority (11).

Chat lab

13 real questions

Facts, maths, files, memory, and questions about things that don't exist. Each answer is graded right or wrong, with the time to first words and to the end.

Speed test

Same prompts, every engine

300-word-piece replies on code and prose, and a 4,500-token prompt to read. Cache off, first try of each, so engines are compared fairly.

Everything here is one run per setup unless a section says so. Our own reruns show why that matters: see One run proves little.

8-bit or 4-bit?

A smaller file leaves more memory for everything else, so we tested whether Linden 1 loses anything at 4-bit. On one run each, it didn't.

8-bit

58/71

26 GB · 18.7 tokens a second

4-bit IQ4_NL

66/71

16 GB · 20.5 tokens a second

  • The 8-point gap is inside what a rerun alone can move, so we read it as "no loss", not "4-bit is better".
  • In the Chat lab, every 4-bit answer that finished was right. Five were cut off when the Mac went to sleep, so that run doesn't count yet.
  • So Macs with 32 to 48 GB get the 4-bit file, and Macs with 64 GB or more get 8-bit or better. The 3-run repeats are next.

The engine matters more than the file

We ran the same Inkling files in two engines: llama.cpp, which Aldergrove's runner uses today, and PolyStrata, a newer engine built for this kind of model. Speeds are word-pieces (tokens) a second.

Engine and fileSizeRead

  • The same 3-bit file writes 2.8 times and reads 5.8 times faster in PolyStrata. Against our 8-bit, it writes about 35% faster and reads about twice as fast.
  • On this Mac, llama.cpp runs "K" files at half speed. IQ4_NL, a non-K 4-bit, is a little faster than 8-bit; the popular UD-Q4_K_XL is the slow kind here. "4-bit is faster" depends on the file type.
  • The draft model adds little. PolyStrata can use a small draft model to guess ahead: about 16% faster on code (25.9 to 29.9), where most guesses are kept, and nothing on prose.
  • PolyStrata reuses what it has already read. In the coding lab it reused 34K of a 39K prompt between turns. Inkling's memory of a prompt can't be trimmed in llama.cpp, so a changed tool list there means reading everything again.
  • PolyStrata needed one fix to run on the M1 Max (a graphics program asked for more threads than this chip allows). After that, no crashes in 52 minutes of lab work.
  • Early, partial: PolyStrata with the 4-bit file passed invoice 17/17 in 9 minutes and recurrence 16/17 in 10, about twice as fast as the same tasks on llama.cpp. The full run is next.

November 25, 2026

Why the first reply is slow

A new chat waits about two minutes for its first words, and writing speed isn't the reason. Before answering, the model reads Aldergrove's setup: about 12,000 tokens describing every tool it can use. At 160 tokens a second, that's over a minute of reading before the first word.

Load Read the setup, 12K tokens Write
  • What we did: a new chat now starts with only the everyday tools and adds mail, Chrome or files when you ask. A first "hi" starts about three times sooner.
  • What's next: warm start, reading the setup once ahead of time so a new chat begins in seconds.

Local against cloud

We tested whether a cloud model writing the plan and a local model writing the code would beat either alone. Five tasks, 74 hidden tests.

  • A cloud model alone won the short tasks. The mixed team cost three quarters as much, took six times longer and scored lower.
  • The local model alone passed 84% for nothing, offline. That's why Aldergrove is built around one local model, with cloud models as an option, not a requirement.

November 7–26, 2026

How small models fail, and what helped

The code is right early, then time runs out
They spend their time writing and rerunning tests until the conversation is full. Plans with a test list, checked steps and trimming old output help.
They judge their own work badly
"Done" while hidden tests fail. Tests run by the app, a second attempt and checked stop help.
They ask questions nobody answers
In a long task, no one is there. The working rules tell them to decide and note the assumption.
They can't see what they build
Measured layout checks, the page tool and boxes drawn on screenshots help.
They loop
Reading 43 files without writing one. Aldergrove notes 20 reads with no change and stops at 40.

What real use taught us

We read every one of our 23 saved test chats and the pages the coding runs built, and fixed what we found the same day. A few of them:

What happenedWhat changed
"Remember that" answered "Noted" without savingThe app saves it and says so
A trip plan was replaced by the model's ownChat keeps the plan you give it
Whole Gmail pages were read three times, about 75 s eachIt pulls just the part it needs
A moved project folder broke every commandIt finds where the folder went
Pictures sent to a model that can't see stalled the chatThe picture becomes a short note
A preview showed another app's page on a busy portThe preview checks it's the right page
"You are done" stopped a brand-new requestOnly a plan made for this request can stop it

What already worked: sourced facts, a map and route of New York, a four-step job in Chrome from start to end, a phishing email flagged, and pages that built clean.

Now

Open questions

  • 8-bit against 4-bit, three runs each. One run each says "no loss"; three will say it with confidence.
  • Should PolyStrata become Aldergrove's engine? It's much faster, but it's a beta and only runs 3-bit and 4-bit files on a Mac.
  • The smaller Macs. The 32, 24 and 16 GB choices follow from the 64 GB results and file sizes. Each gets its own lab.
  • Full precision at 128 GB. Not measured yet. If it's too slow, 8-bit goes first there too.
  • Warm start. Can a new chat start answering in seconds instead of minutes?
